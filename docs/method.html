Collection and completeness

The feed

GitHub publishes public activity (pushes, pull requests, issues, comments, reviews, releases, forks, stars and other event types) through its REST endpoint GET /events. GEP's own measurements since 26 September 2026 show:

  • The endpoint returns the latest 300 public events in three pages of 100; page 4 is refused. The feed runs about 300 seconds behind real time.
  • The feed is one snapshot per second, the same for every client: reads within the same second return the same pages, so more collectors add availability, not coverage.
  • Page 1 holds Push, Create and Delete events; pages 2 and 3 hold all other types.
  • Consecutive snapshots of page 1 do not overlap. Each shows about 100 events, and in most hours GitHub publishes more Push, Create and Delete events per second than one page holds, so a share of them is never shown to any client, however often it reads. Page 1 also skips 5 to 9 percent of seconds for every client.
  • Events of the other types fit pages 2 and 3 and are shown almost completely.
  • Event ids follow the order in which GitHub publishes events, not created_at. Since 8 October 2025 there are two id sequences: one for Push, Create and Delete events and one for all other types.

Collection

Two collectors run on two hosts, a workstation and a rented server. Each reads page 1 about four times a second and pages 2 and 3 once a second; together they send about 42,000 requests an hour. They authenticate with pooled credentials: 48 installations of eight GitHub Apps and five personal access tokens. GEP caps its own use at 50,000 requests an hour, identifies itself with the User-Agent gep-collector/<version> (GitHub Events Preservation), backs off on every rate-limit response, and requests REST API version 2022-11-28. Each collector writes every event the first time it sees it, with the time and position of that read, and a record of every request.

Sealing

Five minutes after an hour ends, GEP merges the collectors' records of that hour by (id, type), keeps the first sighting of each event and notes which collectors received it, and writes the hour as one compressed file sorted by (created_at, id), with its key list and a manifest that carries SHA-256 checksums of the files. Sealing waits while a collector's data is still being transferred; data of a collector that arrives after its hour was sealed is merged into a new version of the hour. A sealed version is never overwritten.

Completeness measurement

For every hour and each id sequence, GEP estimates how many events the feed never showed and how many it showed but GEP did not record. Within a sequence, each page read covers a contiguous range of ids. Over the hour, the ranges GEP read form the covered span, and every stretch of ids between covered ranges is classified by the reads that showed its two edges:

  • Unexposed. The stretch lies between two consecutive snapshots, or between snapshots the page skipped while GEP was reading it at least once a second. The feed never showed these events.
  • Missed. GEP's own reads had a hole of more than a second there, so a snapshot may have been served without being read. A missed stretch is charged at most one page of events per unread snapshot; the rest of it counts as unexposed.

The number of events in a stretch is its length in ids times the density of recorded events per id in that sequence and hour. Each manifest reports, per sequence, the estimated events unexposed and missed and the exposure rate, the estimated share of the sequence's events that the feed showed; and for the hour the capture rate, the estimated share of the shown events that GEP recorded. The two collectors give a second check: the manifest counts the events seen by one or both and reports the Chapman estimate of the hour's total, a lower bound because both read the same feed.

Status of an hour

StatusRule
partialThe hour has no events; or a collector that ran during the hour has no data for it, or had not confirmed the hour complete when it was sealed; or no collector read the feed for more than 60 seconds in total.
degradedAt least one event presumed missed; or a shorter interruption (more than 10 seconds without a read); or an unfinished or truncated collector file was used.
okNone of the above.

A configured collector that did not run during the hour is listed in pollers_missing without lowering the status.

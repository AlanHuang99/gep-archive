GEP: GitHub Events Preservation

GEP keeps a continuous record of GitHub's public events feed. Every hour it publishes the events it received together with a measurement of how complete that hour is.

Figures cover 26 September 2026, 11:00 UTC, to 19 November 2026, 17:00 UTC. The hours table in BigQuery holds the current figures for every hour.

Each hour of events is kept exactly as GitHub's REST API returned them, with a small envelope that records when GEP first received each event and which of its collectors received it. Each hour has a manifest with its counts, checksums, status and estimates of the events the feed never showed and of the events GEP missed. A sealed hour is never overwritten; a correction is released as a new version of that hour with its reason.

Access

Anyone with a Google account can read the data. GEP pays for storage. Queries, downloads and other operations are billed to the user's own Google Cloud project.

BigQuery

Dataset gep-archive.gep in the US location, updated every hour:

TableContents
eventsOne row per event: the top-level fields as columns, the payload as JSON. Partitioned by day, clustered by event type, repository and actor.
pull_requests, pushes, issues, issue_commentsThe payload fields of these event types as typed columns.
hoursOne row per sealed hour with its status and completeness measurement.
events_gharchiveA view of events in GH Archive's column layout.
SELECT type, COUNT(*) AS events
FROM `gep-archive.gep.events`
WHERE event_date = '2026-11-18'
GROUP BY type
ORDER BY events DESC;

The event tables require a filter on event_date. Columns, partitioning and more examples are on the data page. Queries run in, and are billed to, the project of the user who runs them (BigQuery pricing).

Cloud Storage

Bucket gs://gep-archive holds the archive of record: for every hour, one compressed file of newline-delimited JSON, its manifest and its list of event keys. The bucket uses Requester Pays: every request names the requester's billing project, which pays for operations, data retrieval and network transfer.

gcloud storage ls --billing-project=YOUR_PROJECT 'gs://gep-archive/manifests/2026/11/18/*'
gcloud storage cp --billing-project=YOUR_PROJECT gs://gep-archive/raw/2026/11/18/2026-11-18-12.ndjson.gz .

The folders raw/, keys/, variants/ and manifests/ are readable. Files older than 30 days are kept in the Archive storage class, which adds a retrieval charge per gigabyte read.

How it is collected

Two collectors on two hosts read GitHub's GET /events endpoint around the clock, about 42,000 requests an hour, with pooled credentials. Every hour their records are merged, deduplicated, checked and sealed. The completeness of each hour is estimated from gaps in GitHub's event id sequences. The method page describes the feed, the collection and the measurement; the known gaps page lists the hours with the largest losses.
